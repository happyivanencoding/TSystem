# TP 对话接手上下文

`_context` 是 TP 工作区的跨对话接手层，用来让新的 Codex 对话快速知道当前状态、最近交接和下一步检查点。它不是正式文档库，也不替代 `11_docs/`。

## 读取顺序

新对话处理 TP 任务时，先按这个顺序获取上下文：

1. 读本文件。
2. 读 [`active_work.md`](active_work.md)。
3. 如果任务属于固定子项目，读 [`subprojects/`](subprojects/) 下对应文件。
4. 再读当前代码、产物和 `git status`。
5. 如果需要长期项目事实，跳到 `11_docs/` 或项目 README。

## 分层规则

```text
代码/真实产物 > 11_docs 正式文档 > _context 接手状态 > Codex memory/skill
```

如果 `_context`、`11_docs` 和当前代码冲突，以当前代码和真实产物为准，并修正过期文档。

## 什么时候更新 `_context`

- 大任务完成后，新增一份 handoff。
- 当前任务暂停、换方向或留下接手风险。
- 某个子项目的当前状态、下次先看哪里、相关 skill 发生变化。
- 发现 skill 没有按预期触发、误触发或触发词过窄。

## 什么时候更新 `11_docs`

- 长期流程、命令、输入输出路径变化。
- 数据 contract、字段、schema、API payload 或 manifest 格式变化。
- 模块职责、项目地图、生产 runbook、研究方法变化。
- 后续维护者会按文档反复执行。

## 禁止事项

- 不复制 `11_docs` 正文，只链接正式文档并写短状态。
- 不记录一次性聊天流水。
- 不把实验数据、运行证据或大文件放入 `_context`。
- 不在普通业务任务里顺手改 skill；需要改 skill 时单独执行。
